# sesh — Principia Audit (2026-05-31, post-v0.5)

**Reviewed against:** `~/work/principia/architectural-principles.md` + `~/work/principia/ETHOS.md`. No Go-specific principia file present; language-agnostic principles applied directly.
**State at audit:** `main` @ `cbf6727` (v0.5 Lua plugin bridge merged, plus the two Copilot-review follow-ups: `4456d80` `goToLua` stdlib integer types; `cbf6727` ctx through exec seams). 354 unit tests pass; coverage by package: spec 89%, config 93%, engine 78%, plugins 100%, plugins/lua 74%, kitty 88%, tmux 88%, exec 0% (covered indirectly via tmux/kitty).

## Principles applied

Functional core / imperative shell; flat case over nested if/else; canonicalize before comparing; parameterize helpers; ports-and-adapters (the Lua bridge IS the v0.5 port); suggestions-not-auto-set; fail-at-runtime-not-deploy; DRY at the helper level; tagged-tuple branching; YAGNI / Prefer Deletion to Addition; Comments-explain-why-not-what; No-dead-code. Skipped (not applicable): LiveView, CSS/Tailwind, Storybook, reference-vs-local sync, Ash/StreamData, deploy pipeline.

## Findings

### Critical

None. v0.5 did not introduce a correctness bug. The package-level `ctxByLState` map (`bridge.go:32-35`) is concurrency-correct (RWMutex; set/clear bracketed by `callWithCtx`) and the Lua bridge's per-LState isolation is enforced by `TestBridge_OneLStatePerPlugin` (`lua_test.go:278`).

## v0.5-specific observations

- **Lua bridge as a port: clean.** The `plugins.Plugin` / `plugins.Instance` interfaces (`internal/plugins/plugin.go`) are minimal (Name / New / Up / Down / Validate / DryRun) and the Lua adapter (`internal/plugins/lua/plugin.go`) implements them via one mutex + one LState per plugin. The seam is at the right level — the engine never knows whether a plugin is Go or Lua. Compile-time assertions at `plugin.go:271-272` enforce the contract. This is exactly how the principia describes ports-and-adapters.
- **Per-LState isolation, ctx threading: explicit, tested, documented.** `ctxByLState` is a global mutable map, which is normally a code smell — but the comment at `bridge.go:23-35` names the constraint (sesh.* must be callable without altering the Lua call surface), the lifecycle is correct (set in `callWithCtx`, deferred-clear), and `TestBridge_OneLStatePerPlugin` exercises isolation. Documented intent + test coverage flips the smell from "global mutable state" to "named mechanism with bounded scope." Leave it.
- **Mechanism-not-policy preserved end-to-end.** Both embedded Lua plugins (`embed/emacs.lua`, `embed/firefox.lua`) dispatch user hooks (`sesh-open-project`, Firefox `-CreateProfile`) — the bridge never bakes in elisp evaluation or browser session logic. The recipe file (`embed/recipe/sesh.el`) is shipped as a sample, with `sesh init emacs` printing it to stdout for the user to `load-file`. This is the design call locked in for v0.5, and the code matches.
- **Two-hop `RawConfig → any → Lua table` is acknowledged.** Comment at `plugin.go:35-37` names the alternative (direct YAML AST walker) and the rationale for not doing it ("two-hop cost"). This is the right form for a non-critical tradeoff — name the alternative, name the cost, decide visibly.
- **DryRun multi-row shape: the right v0.4 → v0.5 break.** Promoting `Instance.DryRun() ([][]string, error)` to a slice-of-argvs lets multi-step plugins (emacs: probe + spawn + dispatch) preview accurately. The single Go plugin (emacs) was removed in `1e97b21`; no migration carry-cost. Clean.
- **Test coverage on the bridge is solid for behavior, light on the seams.** 17 tests in `lua_test.go` cover Up/Down/Validate/DryRun, error propagation, isolation, wait_for predicate errors. The seams (`execRunner`, `pathLookup`, `fileExists`, `execOsascript`) are all overridable for test, and the existing tests use them. Coverage % (74%) is dragged down by error paths in `goToLua` defaults — addressable if I20 is taken seriously.
- **No new feature flags / opt-ins.** `SESH_USE_LUA_PLUGINS` (the spike-era opt-in) was removed in `90b5c1f`; the Lua loader is default. Good — no zombie config knobs.

## What sesh does WELL

- **The Lua bridge port-seam is textbook.** Engine code (`engine/up.go`, `engine/down.go`) has zero knowledge of Lua — it sees only `plugins.Plugin`. Adding a JS/WASM bridge later would not touch the engine.
- **Mechanism-not-policy lived through v0.5.** The Lua embed plugins dispatch user hooks; sesh never executes elisp or owns browser session state. The recipe file is shipped, not enforced.
- **Tagged sentinels (`Drop bool`) throughout.** `App.Drop`, `Tab.Drop`, `Pane.Drop` give merge a deterministic semantic without magic strings.
- **Pipeline order is explicit and easy to read.** `config/config.go:23-50` reads top-to-bottom as a pipeline; the comment names each step. Loader → ResolveInclude → applyGlobalDefaults → ExpandVars → Validate.
- **Per-LState isolation enforced AND tested.** `TestBridge_OneLStatePerPlugin` (`lua_test.go:278`) exercises the contract. Documentation + test together turns the global ctx-by-LState map from a smell into a named mechanism.
- **Comments name *why*, mostly.** `api_exec.go:53` (`exec_detach` rationale), `bridge.go:23-35` (ctxByLState rationale), `kitty/pgid.go:113-130` (lowest-PID fallback rationale): each names the mechanism and the alternative considered. Tufte-shaped.
- **DryRun shape promotion was net-deletion.** Removing the Go emacs plugin (`1e97b21`, ~210 lines) replaced by `embed/emacs.lua` (~110 lines). PR that deletes earns trust.
