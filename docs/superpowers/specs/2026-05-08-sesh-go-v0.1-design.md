# sesh v0.1 — Go reimplementation, design spec

**Date**: 2026-05-08
**Status**: Design approved; pending implementation plan
**Supersedes**: `bin/sesh` (Python prototype) — retained as reference, not maintained

## Goal

Port [tmuxinator](https://github.com/tmuxinator/tmuxinator) feature parity for the tmux layer of sesh (see [README.md](../../../README.md)), reimplemented in Go with a driver-based architecture that preserves the multi-driver future described in [PLAN.md](../../../PLAN.md).

## Strategic decisions

| Axis | Choice | Why |
|---|---|---|
| Language | Go | Single-binary distribution, fast cold start, no runtime-version pain |
| Plugin model | Modules-only in v0.1; subprocess + JSON-RPC reserved for v1+ | Brainstorm Q2-B: keep plugin door open without paying for it now |
| Tmuxinator relationship | Inspired by, not compatible (no migration tool) | Brainstorm Q3-C: build the right model first |
| Config format | YAML | Multi-line cmds + nested tabs/panes are YAML's sweet spot; tmuxinator users speak it; YAML is a JSON superset |
| Existing Python prototype | Retired; `bin/sesh` kept as design reference | Single source of truth post-v0.1 |
| License | MIT | Matches PLAN.md placeholder |
| Module path | `github.com/ijcd/sesh` | |

## Feature scope (v0.1, tmuxinator-derived)

**Take:**
- Layout: name, root (cwd), tabs (windows), panes, layout, per-tab cwd override, `pre_window`
- Hooks (4 of 7): `pre`, `post`, `on_project_start`, `on_project_stop`
- Attach: `attach: false`, `startup_window`, `startup_pane`
- Templating (minimal): `${VAR}` from `vars:` map + env vars
- Reuse: `extends:` (single, transitive chain) + `${VAR}`
- CLI: `up`, `down`, `ls`, `edit`, `new`, `delete`, `debug`, `capture`, `local`, `validate`, `completion`

**Skip (v0.2+):**
- Hooks 5-7: `on_project_first_start`, `on_project_restart`, `on_project_exit`
- Tmux escape hatches: `tmux_options`, `tmux_command`, `socket_name`
- `kill` (kill-all), `implode`
- ERB / full template engine
- Multiple inheritance (`extends: [a, b]`), named fragments
- Schema version key
- Editor / browser / comms / Spaces drivers
- Plugin SPI (subprocess + JSON-RPC)

## Storage layout

```
~/.config/sesh/
  projects/<name>.yml      concrete project; name = file basename
  templates/<name>.yml     referenced via `extends:`
./.sesh.yml                picked up by `sesh local` from CWD
```

Resolution: `extends: phoenix` → `~/.config/sesh/templates/phoenix.yml`. `extends: ./shared.yml` → relative to declaring file.

## Schema

```yaml
extends: <template-name-or-path>    # optional; single, transitive chain; cycle = error
driver: tmux | kitty                # default tmux (v0.1 only registers tmux)
cwd: <path>                         # ${VAR} expanded; ~ expanded
session: <name>                     # tmux session name override; default = slugged basename
attach: true | false                # default true
startup_window: <title>
startup_pane: <title>
vars:                               # ${VAR} interpolation source
  KEY: value
hooks:
  pre: [...]                        # shell, before driver.Up
  post: [...]                       # shell, after driver.Up
  on_project_start: [...]           # shell, after driver.Up (alias-like; semantic intent)
  on_project_stop: [...]            # shell, during sesh down
pre_window: [...]                   # prepended to every pane's cmd, project-wide
tabs:
  - title: <required>
    cwd: <override>
    cmd: <leaf command>             # mutually exclusive with panes
    driver: <override>
    layout: <tmux layout name or literal>
    pre_window: [...]               # prepended to this tab's panes (after project pre_window)
    panes:
      - title: <required>
        cwd: <override>
        cmd: <required>
```

## Inheritance & merge

`extends:` resolves a chain (single inheritance, transitive, cycle-detect at load). Child merges onto parent per:

| Shape | Rule |
|---|---|
| Scalars | child wins |
| Hashes (maps) | deep-merge per key, child wins on conflict |
| Lists of titled items (tabs, panes) | merge by `title`; child-only titles append; `{title: X, drop: true}` removes |
| Lists of strings (hooks, `pre_window`) | append (parent first, child after) |

**Worked example:**

```yaml
# templates/phoenix.yml
driver: tmux
hooks: { pre: ['direnv allow'] }
tabs:
  - { title: claude, cmd: 'claude --continue' }
  - { title: dev, panes:
      - { title: server, cmd: 'overmind start' }
      - { title: repl,   cmd: 'iex -S mix' } }
  - { title: db, cmd: 'psql ${DB_NAME}' }
```
```yaml
# projects/liberties.yml
extends: phoenix
cwd: ~/work/theliberties/liberties_www
vars: { DB_NAME: liberties_www_dev }
hooks: { pre: ['git pull'] }                # → ['direnv allow', 'git pull']
tabs:
  - { title: db, drop: true }                # removes db
  - { title: notes, cmd: 'nvim NOTES.md' }   # appends
  - { title: dev, panes:                     # merges into existing dev
      - { title: logs, cmd: 'tail -f log/dev.log' } }
```

Resolved: 4 tabs (claude, dev[server,repl,logs], notes), `hooks.pre = [direnv allow, git pull]`, cwd + vars from child.

## Variable substitution

After `extends:`-merge, `${VAR}` in any string field is interpolated:
- Lookup order: `vars:` map → process env → error
- Escape: `$${VAR}` → literal `${VAR}`
- Failure: undefined `${VAR}` aborts with file + key path + missing var
- Scope: every string-typed leaf (`cmd`, `cwd`, hook strings, `session`, etc.)

## Architecture

```
cmd/sesh/                         main.go — cobra entry
internal/
  spec/                           typed config (Project, Tab, Pane, Hooks)
  config/
    loader.go                     YAML → raw tree
    extends.go                    resolve & cycle-check
    merge.go                      apply unified merge rules
    vars.go                       ${VAR} substitution
    validate.go                   containment, required titles, unique siblings
  engine/
    up.go                         hooks.pre → containment → driver.Up → hooks.post + on_start
    down.go                       hooks.on_stop → driver.Down
    debug.go                      render spec + dry-run cmds
    containment.go                VALID_PAIRS — driver compatibility matrix
    hooks.go                      sh -c each line; abort on non-zero
  drivers/
    driver.go                     interface
    tmux/
      driver.go                   Up/Down/Status/Validate/Capture
      session.go                  tmux command builder + dry-run
      capture.go                  parse `tmux list-windows -F` etc.
docs/superpowers/specs/           this spec + future ones
```

### Driver interface

```go
type Driver interface {
    Name() string
    Up(ctx context.Context, p *spec.Project) error
    Down(ctx context.Context, name string) error
    Status(ctx context.Context, name string) (Status, error)
    Validate(p *spec.Project) []ValidationError
    Capture(ctx context.Context) (*spec.Project, error)
}
```

Containment lives in `engine`, not drivers — drivers don't decide who can host them.

```go
var ValidPairs = map[Pair]bool{
    {Parent: "tmux",    Child: "tmux"}:    true,
    {Parent: "tmux",    Child: ""}:        true,  // leaf
    {Parent: "kitty",   Child: "kitty"}:   true,  // future
    {Parent: "kitty",   Child: "tmux"}:    true,  // future
    {Parent: "kitty",   Child: ""}:        true,  // future
    {Parent: "wezterm", Child: "wezterm"}: true,  // future
    {Parent: "wezterm", Child: "tmux"}:    true,  // future
    {Parent: "wezterm", Child: ""}:        true,  // future
}
```

v0.1 registers only `tmux`. Specifying `driver: kitty` errors at validate: "driver kitty not registered".

### Spec types

```go
package spec

type Project struct {
    Name           string             // = file basename
    Cwd            string
    Driver         string             // default "tmux"
    Session        string
    Vars           map[string]string
    Hooks          Hooks
    PreWindow      []string
    Tabs           []Tab
    Attach         *bool              // nil ⇒ true
    StartupWindow  string
    StartupPane    string
}
type Tab struct {
    Title     string
    Cwd       string
    Cmd       string
    Driver    string                  // empty ⇒ inherit
    Layout    string
    PreWindow []string
    Panes     []Pane
}
type Pane struct {
    Title string
    Cwd   string
    Cmd   string
}
type Hooks struct {
    Pre, Post, OnStart, OnStop []string
}
```

## Engine flow

### `sesh up <name> [--force]`

```
1. config.Load(name) → *spec.Project
2. engine.Validate(p)                        // containment, required titles, unique siblings
3. run hooks.pre in calling shell            // abort on non-zero
4. exists := driver.Status(name) == Exists
   if exists && !force:
       attach to existing                     // tmuxinator parity
   else:
       if exists && force: driver.Down + driver.Up
       else: driver.Up(ctx, p)
5. run hooks.post + hooks.on_project_start    // calling shell, abort on non-zero
6. if *p.Attach (nil ⇒ true): switch to session
```

### `sesh down <name>`

```
1. config.Load(name)
2. run hooks.on_project_stop
3. driver.Down(ctx, name)
```

### `sesh debug <name> [--commands-only]`

```
1. config.Load(name)
2. unless --commands-only: print resolved YAML + "--- commands ---"
3. print exact tmux invocations driver.Up would issue (dry-run)
```

### Hook runner

Each `[]string` line executes via `exec.Command("sh", "-c", line)`. Non-zero exit halts the chain; failure surfaces as `hook 'pre' command exited 1: <line>`. stdout/stderr stream to user terminal.

### `pre_window` semantics

Project-level `pre_window` ++ tab-level `pre_window` is joined with ` && ` and prepended to each pane's `cmd`:

```go
parts := append([]string{}, project.PreWindow...)
parts = append(parts, tab.PreWindow...)
if len(parts) > 0 {
    pane.Cmd = strings.Join(parts, " && ") + " && " + pane.Cmd
}
```

## CLI surface

| Command | Behavior |
|---|---|
| `sesh up <name> [--force]` | launch; `--force` ⇒ down + up |
| `sesh down <name>` | run on_stop, kill session |
| `sesh ls` | list `projects/*.yml` |
| `sesh edit <name>` | open in `$EDITOR` |
| `sesh new <name> [--from <other>]` | starter file; `--from` copies an existing project |
| `sesh delete <name>` | rm `projects/<name>.yml` (prompts) |
| `sesh debug <name> [--commands-only]` | render spec + tmux dry-run |
| `sesh capture <name>` | snapshot live session → draft YAML on stdout |
| `sesh local` | use `./.sesh.yml` |
| `sesh validate <name>` | parse + merge + validate, no spawn |
| `sesh completion <shell>` | cobra-built |

`sesh new` default body:
```yaml
# ~/.config/sesh/projects/{{name}}.yml
driver: tmux
cwd: ~/work/{{name}}
tabs:
  - title: shell
  - title: dev
    cmd: echo 'replace me'
```

## Errors

| Class | Format |
|---|---|
| YAML parse | file + line:col + parser message (via `goccy/go-yaml`) |
| Schema validation | file + key path (`tabs[1].panes[0].title`) + reason |
| Containment | "project driver X cannot host tab driver Y; valid: ..." |
| Extends cycle | "extends cycle: a → b → a" |
| Hook failure | "hook 'pre' exited 1: <line>" |
| Missing template | "template not found: <name> (looked in ~/.config/sesh/templates/)" |
| Unregistered driver | "driver X not registered (v0.1: tmux)" |

No JSON output mode in v0.1.

## Testing

| Layer | Approach |
|---|---|
| `spec`, `config` | Pure unit; table-driven for merge & vars |
| `engine` | Unit + driver-mocked integration |
| `drivers/tmux` | Real tmux on isolated socket: `tmux -L sesh-test`. Assert post-Up via `tmux list-windows -F`. CI requires `tmux` |

`go test ./...` runs unit only. Integration gated by `-tags=integration`.
