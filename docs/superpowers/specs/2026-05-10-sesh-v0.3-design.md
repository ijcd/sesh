# sesh v0.3 — global config, include:, discovery hook, direnv — design spec

**Date**: 2026-05-10
**Status**: Design approved (pending user review of this doc); implementation plan to follow
**Builds on**: v0.2 (tmux + kitty drivers, full containment, --launch). Pre-v1 — no backwards-compat constraints.

## Goal

Tighten ergonomics around discovery, composition, and shared defaults. Five small features that compound:

1. **Global `~/.config/sesh/config.yml`** — defaults for scalar/map fields.
2. **`include:` replaces `extends:`** — composition over single-parent inheritance, fragments allowed.
3. **`sesh init <shell>`** — discovery hook prints "sesh project here" on `cd`.
4. **direnv integration** via `$SESH_PROJECT` env var (CWD-aware launch with no args).
5. **Session identity** — status quo; one project name = one session.

No new drivers; no plugin SPI; no breaking infra changes. Pure ergonomic layer on top of v0.2.

## Strategic decisions

| Axis | Choice | Why |
|---|---|---|
| `extends:` removal | Drop entirely; `extends:` errors with clear migration message | Pre-v1, no users to migrate; one mechanism is cleaner |
| Global config scope | Defaults-only; scalar/map fields filled when project omits; never sets list fields | Lists belong in templates (composable, explicit) |
| Merge model | Unchanged from v0.2 (Model B): scalar replace, map deep-merge, titled-list merge-by-title with `drop:`, untitled-list append | Brainstorm Q2-B; powerful + already validated by v0.1/v0.2 |
| Parallel instances | Status quo (one name = one session); separate file via `sesh new --from` for parallel | Brainstorm Q1-Option-0; worktree workflows already differ by directory |
| Discovery semantics | Print message on `cd`, never auto-spawn | Auto-spawn is terrifying; user stays in control |
| direnv coupling | `$SESH_PROJECT` env var convention; no stdlib extension | Smallest viable contract |

## Schema additions

### `~/.config/sesh/config.yml` (new)

```yaml
# Top-level keys, all optional
driver: kitty                 # default driver if project omits (default: tmux)
attach: true                  # default attach behavior (default: true)
editor: nvim                  # override $EDITOR for `sesh edit` (default: $EDITOR > $VISUAL > vi)
state_dir: ~/.local/state/sesh
launch:
  socket_dir: ~/.local/state/sesh/sockets
  wait_timeout: 5s
```

Validation:
- Unknown top-level keys → error.
- List-typed fields (e.g., `hooks`, `pre_window`, `tabs`) at top-level → error ("global config holds defaults only; put list fields in a template").

### `include:` (replaces `extends:`)

```yaml
# Scalar form (1 file)
include: phoenix

# List form (multiple files, processed left-to-right)
include:
  - phoenix
  - hooks/direnv
  - hooks/notify-slack
```

Path resolution:
- Bare name `phoenix` → `<config>/templates/phoenix.yml`.
- Slash-containing or `./relative.yml` → relative to declaring file.
- Sub-paths under templates dir allowed: `hooks/direnv` → `<config>/templates/hooks/direnv.yml`.

`extends:` is removed. Loading a project file with `extends:` produces a clear validation error: `extends: is no longer supported (sesh v0.3+); rename to include:`.

### Session identity

Unchanged. No new flags. `sesh up <name>` uses project name as session name; status check attaches to existing session silently. `--force` recreates.

## Load order (with v0.3 additions)

```
sesh up <name>
  ↓
read ~/.config/sesh/projects/<name>.yml
  ↓ resolve include: chain (cycle-detect)
each included file's body merged left-to-right (Model B rules)
  ↓ apply ~/.config/sesh/config.yml as defaults
fill empty scalar/map fields only; reject list-typed top-level keys
  ↓ expand ${VAR}
  ↓ engine.Validate (containment, schema, driver-specific)
  ↓ engine.Up
```

`sesh up` (no args) reads `$SESH_PROJECT`; errors clearly if neither arg nor env present.

## `sesh init <shell>`

New CLI command. Emits a shell snippet wired into the user's rc:

```sh
eval "$(sesh init zsh)"     # or bash, fish
```

The snippet installs a chpwd-style hook. On each `cd`:

1. If CWD has `.sesh.yml`:
   - Compute a session-scoped guard env var: `SESH_ANNOUNCED_<basename of CWD>=1`.
   - If the guard is set, do nothing (already announced this session).
   - Otherwise: print `sesh: project here — \`sesh local\` to launch`, set the guard.
2. If CWD has no `.sesh.yml`: do nothing.

Never spawns. Never reads beyond `os.Stat`. Pure discovery.

Supported shells:
- `zsh`: chpwd_functions hook
- `bash`: PROMPT_COMMAND
- `fish`: function with --on-variable PWD

Each script is a small Go template baked into the binary.

## direnv connector

Two integration touchpoints, both lightweight:

1. **`$SESH_PROJECT` env var** read by `sesh up` and `sesh local` when no positional arg given. Direnv users put in `.envrc`:
   ```sh
   export SESH_PROJECT=liberties
   ```
   Then `sesh up` (anywhere in the directory) launches `liberties`. Explicit arg always overrides.

2. **`hooks.pre: [direnv allow]`** documented as the canonical pattern. Bridges in the other direction (sesh ensures direnv's env is current before spawning panes that inherit it).

No `direnv use sesh` stdlib extension. No `sesh stdlib`. No auto-up. Discovery hook is the primary "you're entering a project" UX; `$SESH_PROJECT` is the no-args connector.

## Architecture

```
internal/config/
  global.go                    NEW: load + validate ~/.config/sesh/config.yml
  global_test.go               NEW
  include.go                   RENAMED from extends.go; same-shape, single key change
  include_test.go              RENAMED from extends_test.go
  config.go                    extend Load() pipeline: include → global-defaults → vars → validate
  validate.go                  add: extends: → error with migration message; unknown global keys → error
internal/init/
  scripts/zsh.sh.tmpl          NEW: chpwd hook template
  scripts/bash.sh.tmpl         NEW: PROMPT_COMMAND hook template
  scripts/fish.sh.tmpl         NEW: --on-variable PWD function
  init.go                      NEW: render shell-specific snippet
  init_test.go                 NEW
cmd/sesh/
  init.go                      NEW: cobra command emits snippet to stdout
  up.go                        EXTEND: read $SESH_PROJECT when no arg
  local.go                     UNCHANGED — already CWD-driven (./.sesh.yml); $SESH_PROJECT not relevant
  root.go                      register init command
README.md                      add `sesh init` + direnv section, document migration from extends:
```

## Tests planned

| Component | Coverage |
|---|---|
| Global config | empty/missing/corrupted load; defaults applied to scalars; defaults applied to maps; lists in global error; unknown top-level keys error; XDG_CONFIG_HOME respected |
| Defaults integration | project's empty `driver` filled from global; project's set `driver` wins; project's `vars` map deep-merged with global's `vars`; lists never touched (regression: project's `tabs` not affected by anything in global) |
| `include:` parsing | scalar form, list form, mixed string-vs-list at YAML level (use existing StringList machinery), missing file, cycle detection across multiple files (a→b→c→a), `./relative` resolution, fragment files (no driver/tabs) work |
| `extends:` removal | clear error at load time; suggested rename in the message |
| `sesh init <shell>` | each shell template renders; bash/zsh/fish output snapshots; unknown shell errors with valid options listed |
| Discovery hook (Go-side guard logic) | session-scoped guard env var prevents repeat announcements within shell; missing .sesh.yml = silent |
| direnv connector | `sesh up` (no arg) uses $SESH_PROJECT; missing both = error; explicit arg overrides $SESH_PROJECT |

Estimated new tests: ~30. Target total after v0.3: ~250.

## CLI changes

| Command | Change |
|---|---|
| `sesh init <shell>` | NEW: emit shell snippet to stdout |
| `sesh up [name]` | name now optional; falls back to `$SESH_PROJECT` |
| `sesh validate <name>` | now also surfaces extends: → use include: errors |

All other commands unchanged.

## Errors added

| Class | Format |
|---|---|
| `extends:` used | `extends: is no longer supported (sesh v0.3+); rename to include:` |
| Global config unknown key | `~/.config/sesh/config.yml: unknown key %q (allowed: driver, attach, editor, state_dir, launch)` |
| Global config has list field | `~/.config/sesh/config.yml: %q is a list-typed field; lists belong in templates, not global config` |
| `sesh init` unknown shell | `unknown shell %q (supported: zsh, bash, fish)` |
| `sesh up` no arg + no $SESH_PROJECT | `sesh up requires a project name or $SESH_PROJECT env var (set by direnv or shell)` |

## Out of scope (v0.4+)

- `--instance NAME` flag for parallel instances (rare use case; deferred until real demand)
- `direnv use sesh` stdlib extension (over-coupled)
- Auto-up on cd (terrifying)
- Multiple inheritance via `include:` chain (composition already handles this)
- Named fragments / `ref:` semantic (`include:` of small fragments covers this)
- Plugin SPI definition (v0.4)
- Brew tap (separate work, can ship alongside v0.3)
